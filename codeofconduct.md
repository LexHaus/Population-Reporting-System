# Code of Conduct

## 1. Purpose

This Code of Conduct establishes expectations for all team members working on the Population Reporting System coursework project. Our aim is to maintain a respectful, inclusive, and productive environment where everyone can contribute fairly and work towards completing the project successfully.

## 2. Expected Behaviour

All team members are expected to:

* Treat every team member with respect, courtesy, and professionalism.
* Communicate clearly and respond to team messages within a reasonable time.
* Listen to other members' ideas and consider different opinions.
* Share knowledge, offer help, and support teammates who encounter difficulties.
* Complete assigned tasks by agreed deadlines and inform the team early if delays occur.
* Contribute fairly to the project and take responsibility for assigned work.
* Give constructive feedback and accept feedback positively.
* Ensure that all submitted work meets the agreed quality standards.

## 3. Collaboration and Task Management

* Tasks and user stories will be recorded and tracked using GitHub Issues and GitHub Projects.
* Responsibilities will be distributed fairly across the six team members.
* Team members should keep their assigned tasks updated and communicate their progress.
* Significant changes to requirements, responsibilities, or deadlines should be discussed with the group.
* Team members should ask for assistance when needed rather than allowing problems to delay the project.

## 4. GitHub and Development Practices

* Team members should work on appropriate feature branches rather than directly modifying the main branch.
* Changes should be committed regularly with clear and meaningful commit messages.
* Pull requests should be used to review changes before they are merged into the `develop` branch.
* Team members should review code respectfully and address feedback constructively.
* Existing code, configuration files, and another member's work should not be removed or overwritten without discussion.
* Database credentials, passwords, and other sensitive information must not be committed to the repository.
* Team members should test their changes where possible and report known issues honestly.

## 5. Fair Contribution and Academic Integrity
* Every team member is responsible for making a meaningful contribution to the project.
* Work completed by other members must be acknowledged appropriately.
* Team members must not claim another person's work as their own.
* Any external resources, libraries, or code examples must be used in accordance with the relevant licence and coursework rules.
* Team members should follow the institution's academic integrity and collaboration requirements.

## 6. Resolving Disagreements

* Disagreements should be handled calmly and respectfully.
* Team members should discuss problems openly and focus on solutions rather than personal criticism.
* If an issue cannot be resolved between the members involved, the team should discuss it collectively.
* If a serious or persistent problem remains unresolved, the team may seek guidance from the course tutor.

## 7. Accountability

All team members are expected to follow this Code of Conduct throughout the project. Concerns about behaviour or collaboration should be raised respectfully and addressed fairly. The purpose of this code is to support successful teamwork, not to punish honest mistakes.

## 8. Agreement

By participating in the project, team members agree to follow these expectations and contribute to a respectful, fair, and collaborative working environment.
